# 小人形机器人端侧软件与语音交互团队人力阵型

## 一、概述

本文档基于当前端侧软件架构（23个核心模块，ROS2分布式架构），为**小型人形机器人项目**提供端侧软件团队和语音交互团队的人力阵型建议。

**目标团队规模**：
- Phase 1（MVP阶段，0-6个月）：端侧软件 9-11人 + 语音交互 3-4人
- Phase 2（量产阶段，6-12个月）：端侧软件 13-16人 + 语音交互 5-6人

---

## 二、端侧软件团队人力阵型

### 2.1 组织架构

```
端侧软件负责人（1人）
├── 系统架构组（2-3人）
│   ├── 中间件工程师：SM / EM / Gateway / HDS
│   └── 系统工程师：BSP / 启动流程 / 系统监控
├── 运动控制组（3-4人）
│   ├── 运控算法工程师：MC / UC / LC 协调与插件开发
│   ├── 轨迹规划工程师：MS / MP / 动作序列
│   └── 步态/平衡工程师：PnC / WBC / RL策略
├── 感知规划组（2-3人）
│   ├── SLAM工程师：VSLAM / Lidar-SLAM / MapManager
│   └── 感知融合工程师：Perception / 多传感器标定
├── AI与交互组（3-4人）
│   ├── Agent工程师：LLM Agent / Skill Registry / Memory
│   ├── 云端AI工程师：云LLM API / RAG / 知识库 / 云端多模态服务
│   ├── 任务引擎工程师：TE / 任务调度 / VLA任务
│   └── 交互工程师：Interaction / 多模态融合
└── HAL与基础设施组（2人）
    ├── HAL工程师：EtherCAT / Camera / Lidar / Sensor / Audio
    └── 工具链/DevOps工程师：FOTA / DR / RC / CI/CD
```

## 四、团队间协作模式

### 4.1 接口契约

| 协作边界 | 上游（输出方） | 下游（消费方） | 接口形式 |
|----------|-------------|---------------|---------|
| 音频数据流 | HAL_Audio | Interaction | ROS2 Topic `/hal_audio/vad_event` |
| 语音识别结果 | HAL_Audio | Interaction | ROS2 Topic `/hal_audio/speech_recognition_result` |
| TTS播放 | Interaction | HAL_Audio | ROS2 Action `/hal_audio/speak` |
| 交互意图 | Interaction | Agent / TE | ROS2 Topic `/interaction/interaction_event` |
| 任务执行 | TE | MC / MS / MP | ROS2 Action |
| 运动状态 | MC | SM | ROS2 Topic `/sm/robot_state` |
| 健康状态 | HDS | EM / Gateway | MQTT / ROS2 Topic |
| 云LLM请求 | Agent | Gateway | 内部封装 → 云API |
| RAG检索 | Agent | 云端AI工程师 | 向量检索API / 知识库查询 |
| 云端多模态 | Interaction | 云端AI工程师 | 云端ASR/TTS/视觉理解API |
| 云-端数据同步 | Gateway / DR | 云端AI工程师 | 数据上传 / 模型下发 |

### 4.2 日常协作机制

| 机制 | 频率 | 参与方 | 目的 |
|------|------|--------|------|
| 接口对齐会 | 每周 | 模块上下游负责人 | 确认msg/srv/action变更 |
| 联调日 | 每两周 | 全团队 | 跨模块集成测试 |
| 架构评审 | 按需 | 端侧软件负责人+架构组 | 重大设计决策 |
| 供应商对接会 | 每月 | 语音交互负责人+采购 | 科大讯飞等供应商技术对齐 |

### 4.3 代码协作规范

- **接口先行**：msg/srv/action 变更必须提前1周通知下游
- **版本管理**：ROS2接口包独立仓库，语义化版本
- **CI门禁**：所有PR必须通过单元测试+代码审查
- **联调环境**：共享一台实体机器人+仿真环境（Isaac Sim / Gazebo）

| 云LLM API | 供应商方案 | 阿里云/火山方舟/智谱等，统一封装Gateway调用 |

### 风险提示

1. **运控算法是瓶颈**：足式人形运控人才极度稀缺，建议同时培养内部人才+外部顾问
2. **Agent与运控的gap**：LLM Agent人才多来自互联网，缺乏机器人背景，需要与运控团队紧密协作
3. **语音交互供应商依赖**：科大讯飞等供应商的SDK适配和商务条款需要早期锁定
4. **仿真到真实的gap**：Sim-to-real是人形机器人普遍难题，建议预留20%时间用于实机调试
